# 第 15 天：端到端 NPU 视觉项目、性能、复盘与从零重建

## 今日目标与时间

总计约 7 小时：1 小时设计项目，2 小时用 launch 串起相机/处理/NPU 推理，1 小时接可选串口，1 小时 bag 录制与回放，1 小时 NPU/CPU 性能对比，1 小时删除自动产物后从源码重建并答辩。

## 1. 最终项目定义

项目名：`q8b_camera_learning_demo`。

目标数据流：

```text
USB camera
   -> /image_raw [sensor_msgs/msg/Image]
   -> q8b_vision/image_processor
   -> q8b_vision/npu_classifier [QAI AppBuilder / QNNContext / HTP]
   -> /npu_classification [std_msgs/msg/String]
   -> optional q8b_serial/bridge
```

最低完成线：真实图像能进入 ROS2，OpenCV 节点能处理，Q8B NPU 能输出分类，所有节点能用 launch 启动，且 bag 能回放。串口没有硬件时用 socat，不得因为没有串口停在这里。CPU ONNX 节点可以作为对照，但不能代替 NPU 验收。

## 3. 写最终 launch 文件

在 `q8b_vision` 中创建：

```bash
cd ~/ros2_ws/src/q8b_vision
mkdir -p launch config
nano launch/camera_pipeline.launch.py
```

输入以下骨架，并按第 8 天实际驱动包和话题修改：

```python
import os

from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch_ros.actions import Node


def generate_launch_description():
    model_dir = os.path.expanduser('~/q8b_ros2_course/models')
    return LaunchDescription([
        Node(
            package='v4l2_camera',
            executable='v4l2_camera_node',
            name='camera',
            output='screen',
            parameters=[{
                'video_device': '/dev/video0',
                'image_size': [640, 480],
            }],
        ),
        Node(
            package='q8b_vision',
            executable='image_processor',
            name='image_processor',
            output='screen',
            parameters=[{
                'input_topic': '/image_raw',
                'output_topic': '/vision/edges',
            }],
        ),
        Node(
            package='q8b_vision',
            executable='npu_classifier',
            name='npu_classifier',
            output='screen',
            parameters=[{
                'input_topic': '/image_raw',
                'model': os.path.join(model_dir, 'q8b_npu', 'googlenet.bin'),
            }],
        ),
    ])
```

如果你的第 8 天驱动是 `usb_cam`，替换第一项的 package、executable、参数和图像话题；不要保留一个不存在的驱动节点。先检查：

```bash
ros2 pkg executables | grep -E 'v4l2|usb_cam'
```

按第 6 天方式把 `launch/*.launch.py` 加入 `setup.py` 的 `data_files`，然后：

```bash
cd ~/ros2_ws
export ADSP_LIBRARY_PATH="$(python -c "import os, qai_appbuilder; print(os.path.join(os.path.dirname(qai_appbuilder.__file__), 'libs'))")"
colcon build --packages-select q8b_vision --symlink-install
source install/setup.bash
ros2 launch q8b_vision camera_pipeline.launch.py
```

此命令必须在第 14 天的 NPU 虚拟环境和 `ADSP_LIBRARY_PATH` 已准备好的终端中运行。`npu_classifier` 使用 `QNNContext` 的 HTP runtime；如果启动时提示找不到 `qai_appbuilder`，先检查 Python 解释器，不要把它误判为 ROS2 话题错误：

```bash
which python
python -c "import qai_appbuilder; print(qai_appbuilder.__file__)"
echo "$ADSP_LIBRARY_PATH"
```

## 4. 端到端检查清单

另开多个终端检查：

```bash
ros2 node list
ros2 topic list -t
ros2 topic hz /image_raw
ros2 topic hz /vision/edges
ros2 topic echo /npu_classification --once
rqt_graph
```

如果图形界面不可用，使用 `ros2 node info` 逐个检查；不要把 GUI 打不开误判为通信失败。确认：

- 相机节点存在且没有持续报错。
- 图像话题类型为 `sensor_msgs/msg/Image`。
- 边缘图像有输出且频率合理。
- NPU 分类有结果，不是只启动了进程。
- 没有因为 topic 名错误而出现“节点都在但没有连接”。

## 5. 接入串口或虚拟串口

如果已经有第 10 天的 bridge：

```bash
ros2 run q8b_serial bridge --ros-args \
  -p device:="$HOME/q8b_ros2_course/serial/ttyA"
```

先用 CLI 验证：

```bash
ros2 topic pub --once /serial_tx std_msgs/msg/String \
  "{data: 'pipeline online'}"
```

若要把分类自动转发到串口，最小做法是新增一个 subscriber，把 `/npu_classification` 转换为一行文本；不要直接让 NPU classifier 依赖串口包，保持视觉和硬件解耦。写下这个设计取舍：topic 解耦便于无串口时测试、记录和回放。

## 6. 录制最终 bag 并离线重放

终端 A 保持 pipeline 运行；终端 B：

```bash
mkdir -p ~/q8b_ros2_course/bags/final
ros2 bag record \
  /image_raw /vision/edges /npu_classification \
  -o ~/q8b_ros2_course/bags/final/run01
```

运行 30 秒后按 `Ctrl+C`。记录元数据：

```bash
ros2 bag info ~/q8b_ros2_course/bags/final/run01 \
  | tee ~/q8b_ros2_course/notes/final-bag-info.txt
```

停止真实相机和 pipeline，单独启动 `image_processor`、`npu_classifier`，然后回放：

```bash
ros2 bag play ~/q8b_ros2_course/bags/final/run01 --rate 0.25
```

这证明算法不依赖现场硬件也能复现。注意 bag 中若包含 `/npu_classification`，回放它可能与当前 NPU classifier 同时发布同名话题；实验时可只录输入，或用 remap 隔离输出。

## 7. 性能调优实验

用 `btop` 观察，分别测试：

1. 640x480、低频率。
2. 1280x720、低频率。
3. 相同分辨率但降低 bag 回放速率。
4. 关闭边缘处理，只保留 NPU 分类。

每次只改一个变量，记录输入 FPS、输出 FPS、端到端延迟近似值、CPU、内存、温度。优化优先级通常是：降低分辨率/频率、只处理最新帧、选择适合 V68 的轻量量化模型、减少日志，再比较 NPU 与 CPU。不要只看单次推理时间，还要记录模型加载时间、首帧延迟和稳定 FPS。
