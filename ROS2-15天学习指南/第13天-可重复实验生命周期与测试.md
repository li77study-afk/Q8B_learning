## 2. 生命周期节点是什么

普通节点启动后通常立即工作；Lifecycle node 把状态分成 unconfigured、inactive、active、finalized 等，适合相机驱动、硬件和需要安全启停的系统。

检查当前安装：

```bash
ros2 lifecycle --help
ros2 pkg list | grep lifecycle
```

如果有 lifecycle demo，先不要猜可执行文件名，以当前安装实际列出的结果为准：

```bash
ros2 pkg list | grep -i lifecycle
ros2 pkg executables | grep -i lifecycle
```

找到 demo 后再按它的实际包名和可执行名启动，随后观察节点：

```bash
ros2 lifecycle nodes
ros2 lifecycle get /managed_node
ros2 lifecycle set /managed_node configure
ros2 lifecycle set /managed_node activate
```

生命周期的价值是：设备未准备好时不发布“看似有效”的数据，系统可以明确配置、激活和停用，而不是只有进程存活/死亡两种状态。

## 3. QoS 深入实验

用相机或文本话题运行：

```bash
ros2 topic info /image_raw --verbose
ros2 topic echo /image_raw --qos-reliability best_effort --once
ros2 topic echo /image_raw --qos-reliability reliable --once
```

如果第二种收不到而第一种能收到，说明订阅 QoS 与发布者不兼容。记录发布端与订阅端的 reliability、durability、history、depth。

还要理解 transient local：参数、地图、静态信息常希望后来加入的订阅者拿到最后一条；摄像头实时帧通常不需要历史帧。QoS 不是“越可靠越好”，而是按照数据语义选择。

## 4. 时间与模拟时间

查看系统和 ROS 时间：

```bash
ros2 topic list | grep clock || true
ros2 param get /image_processor use_sim_time
```

如果 bag 或仿真使用 `/clock`，节点的 timer 和时间戳可能与墙上时间不同。理解以下区别：

- wall time：操作系统真实时间。
- ROS time：由 ROS clock 提供，可被仿真或 bag 驱动。
- message header stamp：消息产生或采集时间，不一定等于处理时间。

## 5. launch_testing 和最小自动检查

官方教程：

https://docs.ros.org/en/jazzy/Tutorials/Intermediate/Testing/

先学会不写完整测试也能做的检查脚本：

```bash
mkdir -p ~/q8b_ros2_course/scripts
nano ~/q8b_ros2_course/scripts/check_vision.sh
```

输入：

```bash
#!/usr/bin/env bash
set -euo pipefail

test -n "${ROS_DISTRO:-}"
ros2 pkg prefix q8b_vision >/dev/null
ros2 interface show sensor_msgs/msg/Image >/dev/null
echo 'basic ROS2 checks passed'
```

赋予权限并运行：

```bash
chmod u+x ~/q8b_ros2_course/scripts/check_vision.sh
~/q8b_ros2_course/scripts/check_vision.sh
```

- `set -e` 遇到失败立即停止。
- `-u` 使用未定义变量时失败，能早点暴露环境问题。
- `pipefail` 让管道中间命令失败也传递失败状态。
- `test -n` 检查字符串非空。

## 6. DDS Domain ID 与组件化的基本认识

ROS2 节点通过 DDS 自动发现。默认情况下，同一局域网、同一个 `ROS_DOMAIN_ID` 的节点可以互相看到；不同 domain 通常彼此隔离。用两个终端实验：

```bash
export ROS_DOMAIN_ID=23
echo "$ROS_DOMAIN_ID"
ros2 run q8b_basics talker
```

另一个终端也执行 `export ROS_DOMAIN_ID=23` 后运行 listener；再把 listener 的值改为 `24`，观察它不再收到消息。`export` 只影响当前终端及其子进程，实验后可以：

```bash
unset ROS_DOMAIN_ID
echo "domain=${ROS_DOMAIN_ID:-default}"
```

不要在多设备网络上随意使用别人的 domain；在项目记录中写明 domain，避免“节点都启动了但互相看不见”。

ROS2 还支持 component composition：多个 C++ 节点可以装入同一个进程，减少进程间复制并改善高带宽图像管线的性能。先用 CLI 认识它，不要求今天把 Python 节点改写成 C++：

```bash
ros2 component --help
ros2 component list
```

这解释了为什么真实项目有时会出现 `component_container`、component registry 和 load/unload，而不是每个节点都由独立命令启动。第 9、14 天的图像处理先保持独立进程，便于调试；性能确实不足时再研究组件化。
