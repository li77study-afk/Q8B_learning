# 第 2 天：安装 ROS2、source、官方 demo 与 CLI 探测

## 今日目标与时间

总计约 6 小时：1.5 小时安装与依赖，1 小时理解环境变量和 `source`，1.5 小时官方 talker/listener，1 小时 ROS2 CLI 探测，1 小时故障演练与记录。

## 1. 每次开终端的固定动作

```bash
whoami
pwd
echo "$SHELL"
echo "$ROS_DISTRO"
```

`$ROS_DISTRO` 为空很正常，因为还没有加载 ROS2。`$SHELL` 是默认 shell；本课程命令按 Bash 写。

创建今日记录和工作空间骨架：

```bash
mkdir -p ~/q8b_ros2_course/notes ~/ros2_ws/src
cd ~/ros2_ws
pwd
find . -maxdepth 1 -print
```

ROS2 工作空间的 `src` 放源码；`build`、`install`、`log` 会由 `colcon` 自动生成，不能手写到 `src` 里。

## 2. 原生 apt 路线（仅当第 1 天确认官方支持）

先阅读官方当前页面，不要照抄旧博客：

https://docs.ros.org/en/jazzy/Installation/Ubuntu-Install-Debs.html

官方流程通常包括 locale、Ubuntu 仓库、ROS2 apt 源、桌面版和开发工具。命令中的 `<ROS_DISTRO>` 必须替换成官方明确支持的发行版：

```bash
sudo apt update
sudo apt install -y ros-<ROS_DISTRO>-desktop ros-dev-tools
```

- `sudo` 临时借用管理员权限；密码输入不显示。
- `apt update` 更新软件包索引，不等于升级系统。
- `apt install -y` 安装并自动回答 yes；初学时也可以去掉 `-y` 阅读确认列表。
- `ros-<ROS_DISTRO>-desktop` 包含 ROS2、RViz2、demo 和常用 GUI；若存储空间不足，使用 `ros-<ROS_DISTRO>-ros-base`，但没有 GUI。
- `ros-dev-tools` 提供开发时需要的 colcon、rosdep 等工具。

安装后不要马上写入 `.bashrc`，先手动验证：

```bash
source /opt/ros/<ROS_DISTRO>/setup.bash
echo "$ROS_DISTRO"
which ros2
ros2 --help | less
```

- `source` 在当前 shell 执行 setup 脚本，修改当前终端的环境变量；直接运行脚本不能保留这些变量。
- `which ros2` 查实际可执行文件路径。
- `less` 分页查看，按 `q` 退出。

确认正确后再设置新终端自动加载：

```bash
grep -qxF 'source /opt/ros/<ROS_DISTRO>/setup.bash' ~/.bashrc || \
  echo 'source /opt/ros/<ROS_DISTRO>/setup.bash' >> ~/.bashrc
source ~/.bashrc
```

`grep -qxF` 检查整行是否已经存在；`||` 表示前一条失败时才追加，避免重复写入。反斜杠 `\` 表示命令换行续写。

## 3. Docker 路线（Ubuntu 26.04 无官方 deb 时使用）

Docker 不是 ROS2 本体，而是隔离环境。先确认官方镜像标签和 ARM64 支持：

https://hub.docker.com/_/ros

在 Q8B 执行：

```bash
sudo apt update
sudo apt install -y docker.io
sudo usermod -aG docker "$USER"
newgrp docker
docker version
docker pull ros:<ROS_DISTRO>-ros-base
```

- `docker.io` 是 Ubuntu 打包的 Docker；`usermod -aG docker "$USER"` 把当前用户加入 docker 组。
- `newgrp docker` 只为当前 shell 刷新组身份；也可以注销再登录。
- `docker pull` 下载镜像，镜像类似可复制的系统模板。

启动带工作空间挂载的容器：

```bash
docker run --rm -it --net=host \
  --name ros2dev \
  -v "$HOME/ros2_ws:/root/ros2_ws" \
  ros:<ROS_DISTRO>-ros-base bash
```

- `--rm` 退出后删除容器本身；源码在 `-v` 挂载的宿主机目录中，不会消失。
- `-it` 提供交互式终端。
- `--net=host` 让 DDS 使用宿主机网络，便于 ROS2 自动发现。
- `-v 宿主机:容器` 把两个路径映射起来。
- 进入容器后执行 `source /opt/ros/<ROS_DISTRO>/setup.bash`，离开用 `exit`。

开第二个 Q8B 终端进入同一个容器：

```bash
docker exec -it ros2dev bash
source /opt/ros/<ROS_DISTRO>/setup.bash
```

如果只使用 `ros-base`，第 2 天先完成 CLI；GUI 和摄像头 Docker 透传放到第 8、12 天验证。

## 4. 官方 talker/listener

在终端 A：

```bash
source /opt/ros/<ROS_DISTRO>/setup.bash
ros2 run demo_nodes_cpp talker
```

在终端 B：

```bash
source /opt/ros/<ROS_DISTRO>/setup.bash
ros2 run demo_nodes_py listener
```

`ros2 run <package> <executable>` 的三个部分是 ROS2 CLI、软件包名、可执行程序名。预期 A 持续显示 `Publishing`，B 显示 `I heard`。用 `Ctrl+C` 分别停止。

若包不存在：

```bash
ros2 pkg list | grep demo
ros2 pkg prefix demo_nodes_cpp
ros2 doctor
```

`ros2 pkg prefix` 显示包安装前缀；`ros2 doctor` 检查环境。若 `ros2` 命令不存在，先检查 `source`；若 apt 安装失败，回到官方支持矩阵，不要继续拼接源地址。

## 5. 认识 ROS2 CLI 的“侦查顺序”

重新启动 talker 后，在终端 B 依次执行：

```bash
ros2 node list
ros2 node info /talker
ros2 topic list -t
ros2 topic info /chatter
ros2 topic echo /chatter --once
ros2 topic hz /chatter
```

- `node list` 列运行中的节点。
- `node info` 显示节点的发布、订阅、服务和动作。
- `topic list -t` 同时显示话题类型；`/chatter` 通常是 `std_msgs/msg/String`。
- `topic info` 看发布者、订阅者和 QoS 摘要。
- `echo --once` 只打印一条消息后退出；不加它会持续打印。
- `hz` 估算频率；按 `Ctrl+C` 停止。

练习服务和参数的探测：

```bash
ros2 service list
ros2 param list /talker
ros2 interface show std_msgs/msg/String
```

ROS2 的通信接口是类型化的；`interface show` 是查看消息字段的第一工具。

## 6. 理解 `source` 的实验

打开两个终端，终端 A 执行：

```bash
env | grep -E 'ROS|AMENT|RMW'
```

终端 B 不执行 source，观察：

```bash
echo "$ROS_DISTRO"
which ros2 || true
```

环境变量只属于当前进程及其子进程；终端 B 不会自动继承终端 A 的 `source`。这就是为什么每个新终端都要 source。
